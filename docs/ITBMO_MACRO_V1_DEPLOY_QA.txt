======================================================================
A. ORDEN DE IMPLEMENTACIÓN
======================================================================
1. Crear/usar una rama de prueba basada en la baseline suministrada.
2. Reemplazar/crear ÚNICAMENTE los archivos entregados en esta macrotanda.
3. En Supabase SQL Editor, usar/crear una query claramente nombrada, por ejemplo:
   ITBMO - Commerce Growth Macro V1 - 2026-09-11
4. Pegar supabase/migrations/20260911_commerce_growth_macro_v1.sql.
5. Presionar RUN. Guardar la query no aplica cambios por sí solo.
6. Confirmar éxito completo antes de deploy.
7. Para probar checkout/promociones en Vercel Preview, configurar env de Preview:
   ITBMO_PREVIEW_PAYMENT_BYPASS=false
8. Redeploy Preview.
9. Ejecutar QA por bloques en el orden siguiente.

E. QA 4 · PROMOTIONS ENGINE
======================================================================
Mantener ITBMO100 inactive durante pruebas iniciales.

Crear PROMO DE TEST temporal con máximo 2 redenciones:
- percentage (valor cualquiera de QA)
- max_redemptions=2
- active=true

Validar:
- mayúsculas/minúsculas del código.
- descuento visible correcto.
- servidor calcula final amount.

- trip se genera.
- payment table NO recibe falso amount=0 por esta promoción.
- payment status devuelve entitlement_source=promotion.
- Context e Info Chat quedan autorizados.
- tercer uso recibe exhausted.

Probar también:
- código inexistente
- active=false
- starts_at futuro
- expires_at pasado
- verified_only si se decide utilizar
- registered_only si se decide utilizar

Al terminar QA: desactivar todos los TEST codes.
